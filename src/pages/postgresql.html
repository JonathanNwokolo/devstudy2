🐘 Onde os dados moram

PostgreSQL

Toda aplicação séria guarda dados em algum lugar. O PostgreSQL é o banco de dados relacional open source mais avançado do mundo — e você conversa com ele usando a linguagem SQL, que é mais simples do que parece.

🐘

O que é o PostgreSQL?

É um banco de dados relacional gratuito e open source, conhecido por ser robusto e seguir os padrões. Pense em planilhas conectadas: cada tabela tem colunas (campos) e linhas (registros) — como uma tabela usuarios com colunas id, nome e email.

⚙️
Como rodar Instale o PostgreSQL e use o terminal psql para se conectar: psql -U postgres -d meu_banco. Ferramentas visuais como o pgAdmin ou o DBeaver também ajudam quem está começando.

🔍 SELECT — consultar dados

PostgreSQL 
-- Todas as colunas de todos os usuários
SELECT * FROM usuarios;

-- Só nome e email
SELECT nome, email FROM usuarios;

-- Com filtro e ordenação
SELECT nome FROM usuarios
WHERE idade >= 18
ORDER BY nome ASC
LIMIT 10;
💡
WHERE é seu melhor amigo É a cláusula que filtra linhas. Combine com AND, OR e LIKE '%texto%' para buscas mais espertas.

✏️ INSERT, UPDATE & DELETE

PostgreSQL 
-- Criar um registro
INSERT INTO usuarios (nome, email)
VALUES ('Ana', 'ana@email.com');

-- Atualizar (SEMPRE com WHERE!)
UPDATE usuarios SET email = 'novo@email.com'
WHERE id = 1;

-- Apagar (SEMPRE com WHERE!)
DELETE FROM usuarios WHERE id = 1;
⚠️
O erro clássico Esquecer o WHERE em um UPDATE ou DELETE altera/apaga todas as linhas da tabela. Sempre confira antes de executar!

🔗 JOIN — juntando tabelas

O "relacional" vem daqui: conectar dados de tabelas diferentes.

PostgreSQL 
-- Pedidos com o nome do usuário que fez
SELECT pedidos.id, usuarios.nome, pedidos.total
FROM pedidos
JOIN usuarios ON pedidos.usuario_id = usuarios.id;

🧬 Os tipos de JOIN

A diferença está em quais linhas aparecem quando não há correspondência entre as tabelas.

JOINTraz...
INNER JOINSó linhas com correspondência nas duas tabelas
LEFT JOINTodas da esquerda + as que casam da direita (resto vira NULL)
RIGHT JOINTodas da direita + as que casam da esquerda
FULL JOINTodas das duas, casando quando possível
💡
LEFT JOIN é o mais usado Quer "todos os usuários, tenham eles pedidos ou não"? Use LEFT JOIN — os sem pedido aparecem com colunas NULL.

🏗️ Criar tabelas & chaves

Antes de inserir dados, você define a estrutura. As chaves são o que conecta as tabelas.

PostgreSQL 
CREATE TABLE usuarios (
  id SERIAL PRIMARY KEY,        -- SERIAL: auto-incremento do PostgreSQL
  nome VARCHAR(100) NOT NULL,   -- texto obrigatório
  email VARCHAR(150) UNIQUE,    -- não pode repetir
  criado_em TIMESTAMP DEFAULT NOW()
);

CREATE TABLE pedidos (
  id SERIAL PRIMARY KEY,
  total NUMERIC(10,2),          -- NUMERIC para valores monetários
  usuario_id INTEGER REFERENCES usuarios(id) -- chave estrangeira
);
🔑
PK x FK A chave primária (PK) identifica unicamente cada linha. A chave estrangeira (FK) aponta para a PK de outra tabela — é o que torna o banco "relacional".

📊 Agrupar & somar (GROUP BY)

Funções de agregação resumem várias linhas em um valor: total, média, contagem...

PostgreSQL 
-- Quantos usuários existem?
SELECT COUNT(*) FROM usuarios;

-- Valores únicos (sem repetir)
SELECT DISTINCT cidade FROM usuarios;

-- Total gasto por usuário
SELECT usuario_id, SUM(total) AS gasto_total
FROM pedidos
GROUP BY usuario_id
HAVING SUM(total) > 100   -- filtra grupos (WHERE não funciona aqui)
ORDER BY gasto_total DESC;
FunçãoRetorna
COUNT()Quantidade de linhas
SUM()Soma dos valores
AVG()Média
MAX() / MIN()Maior / menor valor
⚠️
WHERE x HAVING WHERE filtra linhas antes de agrupar; HAVING filtra os grupos depois do GROUP BY.

🐘 O que torna o PostgreSQL especial

Além do SQL padrão, o Postgres traz recursos poderosos que outros bancos não têm de forma tão completa.

PostgreSQL 
-- Coluna JSONB: guarda JSON com índice e consulta rápida
CREATE TABLE eventos (
  id SERIAL PRIMARY KEY,
  dados JSONB
);

INSERT INTO eventos (dados)
VALUES ('{"tipo": "clique", "x": 10}');

-- Consultar dentro do JSON
SELECT dados->>'tipo' FROM eventos
WHERE dados->>'tipo' = 'clique';

-- RETURNING devolve a linha recém-criada (recurso do Postgres)
INSERT INTO usuarios (nome) VALUES ('Ana') RETURNING id;
RecursoPara quê
JSONBGuardar dados flexíveis (estilo NoSQL) dentro do SQL
SERIALColuna auto-incrementada (IDs)
RETURNINGObter os dados inseridos/atualizados na mesma query
ILIKEBusca de texto ignorando maiúsculas/minúsculas

🪆 Subconsultas & CTE (WITH)

Quebre consultas grandes em partes legíveis. A CTE dá nome a um resultado temporário.

PostgreSQL 
-- Subconsulta
SELECT nome FROM usuarios
WHERE id IN (SELECT usuario_id FROM pedidos WHERE total > 100);

-- CTE: mesmo resultado, mais legível
WITH grandes_pedidos AS (
  SELECT usuario_id FROM pedidos WHERE total > 100
)
SELECT u.nome
FROM usuarios u
JOIN grandes_pedidos g ON g.usuario_id = u.id;

🛠️ Alterar & apagar estrutura

PostgreSQL 
ALTER TABLE usuarios ADD COLUMN telefone VARCHAR(20);
ALTER TABLE usuarios DROP COLUMN telefone;
ALTER TABLE usuarios RENAME COLUMN nome TO nome_completo;

TRUNCATE TABLE pedidos;        -- esvazia a tabela
DROP TABLE IF EXISTS pedidos;  -- apaga a tabela
🚨
Sem volta DROP e TRUNCATE apagam tudo de uma vez. Faça backup (pg_dump) antes de rodar em produção.

⚡ Índices & EXPLAIN

Índices aceleram buscas em tabelas grandes, como o índice de um livro.

PostgreSQL 
CREATE INDEX idx_usuarios_email ON usuarios(email);

-- Índice para colunas JSONB
CREATE INDEX idx_eventos_dados ON eventos USING GIN (dados);

-- Veja o plano de execução e o tempo real
EXPLAIN ANALYZE SELECT * FROM usuarios WHERE email = 'ana@email.com';
💡
Seq Scan x Index Scan No EXPLAIN, Seq Scan lê a tabela inteira; Index Scan usa o índice. Indexe colunas de WHERE, JOIN e ORDER BY.

🔒 Transações (ACID)

Vários comandos viram uma operação só: ou todos funcionam, ou nenhum.

PostgreSQL 
BEGIN;

UPDATE contas SET saldo = saldo - 100 WHERE id = 1;
UPDATE contas SET saldo = saldo + 100 WHERE id = 2;

COMMIT;      -- confirma
-- ROLLBACK; -- desfaz tudo

SQL Injection Nunca concatene texto do usuário na query. Use consultas parametrizadas ($1, $2...) ou um ORM como Prisma. Veja também SQL & MySQL.
🧠
SQL x NoSQL Bancos SQL como o PostgreSQL usam tabelas e esquema definido. Bancos NoSQL (MongoDB) guardam documentos flexíveis tipo JSON. O bacana é que o Postgres faz os dois: com JSONB você tem a flexibilidade do NoSQL sem abrir mão do SQL.
