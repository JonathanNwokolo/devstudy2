Acessibilidade (a11y)

Acessibilidade é construir sites que qualquer pessoa consiga usar — inclusive quem enxerga pouco, usa leitor de tela ou navega só pelo teclado. Bônus: também melhora o SEO e a experiência de todos.

🌍

Por que isso importa?

Mais de 1 bilhão de pessoas no mundo têm alguma deficiência. Um site acessível não é "extra" — é o básico bem feito. E a maioria das melhorias é simples de aplicar.

🏷️ Use HTML semântico

Tags com significado ajudam leitores de tela a entender a página.

✅ Faça

<button>Enviar</button>
<nav>...</nav>
<main>...</main>
<h1>Título</h1>

❌ Evite

<div onclick="...">Enviar</div>
<div class="nav">...</div>
<div class="title">Título</div>

🖼️ Texto alternativo (alt)

HTML 
<!-- Descreva o conteúdo da imagem -->
<img src="grafico.png" alt="Vendas cresceram 30% em 2024" />

<!-- Imagem só decorativa? alt vazio -->
<img src="enfeite.svg" alt="" />
💡
Regra do alt Descreva a informação, não a aparência. "Logo da empresa" é melhor que "imagem azul". Decoração pura usa alt="".

⌨️ Navegação por teclado

Teste: navegue no seu site só com a tecla Tab. Tudo clicável deve ser alcançável e ter foco visível.

🚫
Nunca remova o foco Evite outline: none; sem colocar um foco alternativo. Quem usa teclado precisa enxergar onde está.

📝 Formulários com label

HTML 
<label for="email">E-mail</label>
<input id="email" type="email" />

<!-- Ícone sem texto? Use aria-label -->
<button aria-label="Fechar">✕</button>

🎨 Contraste de cores

Texto precisa de contraste suficiente com o fundo (mínimo 4.5:1 para texto normal, segundo a WCAG).

📑 Hierarquia de títulos

Leitores de tela navegam pelos títulos. A ordem (h1 → h2 → h3) deve ser lógica, sem pular níveis.

✅ Faça

<h1>Título da página</h1>
  <h2>Seção</h2>
    <h3>Subseção</h3>
  <h2>Outra seção</h2>

❌ Evite

<h1>Título</h1>
  <h4>Pulou h2 e h3</h4>
<!-- h grande só por
     causa do tamanho -->
💡
Tamanho é trabalho do CSS Escolha o nível do título pelo significado, não pela aparência. Para deixar maior ou menor, use CSS.

🗺️ Landmarks & roles ARIA

Tags semânticas criam "regiões" que o leitor de tela usa para pular direto ao conteúdo.

HTML 
<header>...</header>   <!-- role="banner" -->
<nav>...</nav>         <!-- role="navigation" -->
<main>...</main>       <!-- role="main" -->
<footer>...</footer>   <!-- role="contentinfo" -->

<!-- Estado dinâmico para leitores de tela -->
<button aria-expanded="false">Menu</button>
<div aria-live="polite">Salvo!</div> <!-- anuncia mudanças -->
📢
aria-live Avisos que aparecem sem recarregar a página (ex: "item adicionado ao carrinho") precisam de aria-live para serem anunciados a quem usa leitor de tela.

🎯 Gerenciar o foco

Ao abrir um modal ou enviar um formulário, mova o foco para o lugar certo — não deixe o usuário perdido.

HTML / JS 
<!-- Link "pular para o conteúdo" (some até receber foco) -->
<a href="#main" class="skip-link">Pular para o conteúdo</a>

// Ao abrir um modal, foque nele:
modal.querySelector("h2").focus();
🧭
WCAG & ARIA A WCAG é o guia oficial de acessibilidade. O ARIA adiciona informação para leitores de tela — mas a primeira regra do ARIA é: se dá pra usar HTML semântico, use HTML semântico.
