HTML

Top 10 Erros em HTML

Erros de marcação que afetam acessibilidade, SEO e funcionamento.

01 Alta Frequência

Tags não fechadas corretamente

❌ Errado 
<div>
  <p>Texto aqui
  <span>Mais texto</span>
</div>
✅ Correto 
<div>
  <p>Texto aqui</p>
  <span>Mais texto</span>
</div>
💡

Use extensões como "Auto Close Tag" no VS Code para evitar esse erro.

02 Alta Frequência

Esquecer atributo alt em imagens

❌ Errado 
<img src="foto.jpg">
✅ Correto 
<img src="foto.jpg" alt="Descrição da imagem">
💡

Essencial para acessibilidade e SEO. Leitores de tela dependem do alt.

03 Média Frequência

Usar múltiplos IDs iguais

❌ Errado 
<div id="main">Conteúdo 1</div>
<div id="main">Conteúdo 2</div>
✅ Correto 
<div id="main-1">Conteúdo 1</div>
<div id="main-2">Conteúdo 2</div>
<!-- Ou use classes -->
<div class="main">Conteúdo</div>
💡

IDs devem ser únicos na página. Para elementos repetidos, use classes.

04 Alta Frequência

Estrutura semântica incorreta

❌ Errado 
<div class="header">...</div>
<div class="navigation">...</div>
<div class="content">...</div>
✅ Correto 
<header>...</header>
<nav>...</nav>
<main>...</main>
<footer>...</footer>
💡

Tags semânticas melhoram SEO, acessibilidade e manutenção do código.

05 Média Frequência

Pular níveis de heading

❌ Errado 
<h1>Título Principal</h1>
<h4>Subtítulo</h4>  <!-- Pulou h2, h3 -->
✅ Correto 
<h1>Título Principal</h1>
<h2>Subtítulo</h2>
<h3>Sub-subtítulo</h3>
💡

Headings criam hierarquia. Não pule níveis - use CSS para estilizar tamanhos.

06 Baixa mas Importante

Links sem href ou com href="#"

❌ Errado 
<a onclick="doSomething()">Clique</a>
<a href="#">Link fake</a>
✅ Correto 
<a href="/pagina">Link real</a>
<button onclick="doSomething()">Ação</button>
💡

Use <a> para navegação, <button> para ações. Acessibilidade importa!

07 Média Frequência

Formulários sem labels

❌ Errado 
<input type="text" placeholder="Nome">
✅ Correto 
<label for="nome">Nome:</label>
<input type="text" id="nome" name="nome">
💡

Labels associados melhoram UX (clique no label foca no input) e acessibilidade.

08 Alta Frequência

Inline styles excessivos

❌ Errado 
<p style="color: red; font-size: 16px; 
   margin: 10px; padding: 5px;">Texto</p>
✅ Correto 
<!-- HTML -->
<p class="destaque">Texto</p>

/* CSS */
.destaque {
  color: red;
  font-size: 16px;
}
💡

Separe estrutura (HTML) de apresentação (CSS). Facilita manutenção.

09 Baixa Frequência

Tabelas para layout

❌ Errado (anos 2000) 
<table>
  <tr>
    <td>Menu</td>
    <td>Conteúdo</td>
  </tr>
</table>
✅ Correto (moderno) 
<div class="layout">
  <aside>Menu</aside>
  <main>Conteúdo</main>
</div>
/* CSS: display: flex ou grid */
💡

Tabelas são para dados tabulares. Use Flexbox ou Grid para layouts.

10 Média Frequência

Esquecer meta viewport

❌ Errado 
<head>
  <title>Meu Site</title>
</head>
✅ Correto 
<head>
  <meta charset="UTF-8">
  <meta name="viewport" 
    content="width=device-width, initial-scale=1.0">
  <title>Meu Site</title>
</head>
💡

Essencial para sites responsivos. Sem isso, mobile mostra versão desktop minúscula.

CSS

Top 10 Erros em CSS

Problemas de estilização que causam layouts quebrados e bugs visuais.

01 Alta Frequência

Esquecer box-sizing: border-box

❌ Problema 
.box {
  width: 100px;
  padding: 20px;
  border: 5px solid;
}
/* Largura real: 150px! */
✅ Solução 
*, *::before, *::after {
  box-sizing: border-box;
}
.box {
  width: 100px; /* Largura real: 100px */
}
💡

Adicione isso no início de todo CSS. Padding e border ficam dentro do width.

02 Alta Frequência

Usar height: 100% sem contexto

❌ Não funciona 
.container {
  height: 100%; /* Não faz nada! */
}
✅ Funciona 
html, body {
  height: 100%;
}
.container {
  height: 100%; /* Agora sim! */
}
/* Ou use: */
.container {
  min-height: 100vh;
}
💡

% é relativo ao pai. Se o pai não tem altura definida, não funciona. Use vh.

03 Alta Frequência

Centralizar verticalmente incorretamente

❌ Tentativas frustradas 
.box {
  vertical-align: middle; /* Não funciona */
  margin: auto; /* Só horizontal */
}
✅ Soluções modernas 
/* Flexbox */
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}

/* Grid */
.container {
  display: grid;
  place-items: center;
}
💡

Flexbox e Grid resolvem centralização de forma simples e consistente.

04 Média Frequência

Especificidade muito alta

❌ Difícil de sobrescrever 
body div.container #main .content p.text {
  color: red;
}
/* Especificidade: 0,1,2,4 */
✅ Simples e reutilizável 
.text-red {
  color: red;
}
/* Especificidade: 0,0,1,0 */
💡

Mantenha especificidade baixa. Evite IDs no CSS. Use classes bem nomeadas.

05 Alta Frequência

Usar !important desnecessariamente

❌ Guerra de !important 
.button {
  color: red !important;
}
.button-blue {
  color: blue !important; /* Quem ganha? */
}
✅ Solução limpa 
.button {
  color: red;
}
.button.button-blue {
  color: blue; /* Maior especificidade */
}
💡

!important é último recurso. Resolva problemas com especificidade adequada.

06 Média Frequência

Z-index sem position

❌ Não funciona 
.element {
  z-index: 9999; /* Ignorado! */
}
✅ Funciona 
.element {
  position: relative; /* Necessário! */
  z-index: 10;
}
💡

z-index só funciona em elementos posicionados (relative, absolute, fixed, sticky).

07 Média Frequência

Margin collapse inesperado

❌ Comportamento confuso 
.box1 { margin-bottom: 20px; }
.box2 { margin-top: 30px; }
/* Espaço total: 30px (não 50px!) */
✅ Evitar collapse 
/* Use padding no container */
.container { padding: 1px; }

/* Ou Flexbox/Grid */
.container { display: flex; flex-direction: column; }

/* Ou gap */
.container { display: flex; gap: 30px; }
💡

Margins verticais colapsam. Flexbox e Grid não têm esse comportamento.

08 Baixa mas Importante

Não usar unidades relativas

❌ Problema de acessibilidade 
body {
  font-size: 16px; /* Fixo */
}
h1 {
  font-size: 32px; /* Fixo */
}
✅ Acessível e responsivo 
:root {
  font-size: 16px; /* Base */
}
body {
  font-size: 1rem;
}
h1 {
  font-size: 2rem; /* Escala com preferência do usuário */
}
💡

rem e em respeitam configurações de acessibilidade do usuário.

09 Média Frequência

Overflow hidden escondendo conteúdo

❌ Conteúdo cortado 
.card {
  overflow: hidden;
  /* Box-shadow, tooltips, dropdowns 
     podem ser cortados! */
}
✅ Uso consciente 
/* Use apenas quando necessário */
.card {
  overflow: visible; /* Padrão */
}
.card-image {
  overflow: hidden; /* Só na imagem */
  border-radius: 8px;
}
💡

overflow: hidden afeta todos os filhos. Aplique apenas onde necessário.

10 Alta Frequência

Não testar em diferentes browsers

❌ Funciona só no Chrome 
.element {
  backdrop-filter: blur(10px);
  /* Sem fallback para Firefox antigo */
}
✅ Com fallback 
.element {
  background: rgba(255,255,255,0.9);
}
@supports (backdrop-filter: blur(10px)) {
  .element {
    background: rgba(255,255,255,0.5);
    backdrop-filter: blur(10px);
  }
}
💡

Use caniuse.com para verificar suporte. Sempre forneça fallbacks.

JavaScript

Top 15 Erros em JavaScript

Os bugs mais comuns que todo desenvolvedor JavaScript enfrenta.

01 Alta Frequência

Cannot read property of undefined/null

❌ Erro comum 
const user = null;
console.log(user.name); 
// TypeError: Cannot read property 'name' of null
✅ Verificação segura 
// Optional chaining (ES2020)
console.log(user?.name); // undefined

// Ou verificação tradicional
if (user && user.name) {
  console.log(user.name);
}

// Com valor padrão
const name = user?.name || 'Anônimo';
💡

Use optional chaining (?.) e nullish coalescing (??) para código seguro.

02 Alta Frequência

Comparação com == ao invés de ===

❌ Comparação solta 
0 == ""      // true (WAT?)
0 == false   // true
null == undefined // true
"1" == 1     // true
✅ Comparação estrita 
0 === ""      // false
0 === false   // false
null === undefined // false
"1" === 1     // false

// Sempre use === e !==
💡

=== compara valor E tipo. == faz coerção de tipo e causa bugs sutis.

03 Alta Frequência

var vs let/const e hoisting

❌ Problemas com var 
console.log(x); // undefined (não erro!)
var x = 5;

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 3, 3, 3 (não 0, 1, 2!)
✅ Usar let e const 
console.log(x); // ReferenceError
let x = 5;

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 0, 1, 2 ✓

// Use const para valores que não mudam
const PI = 3.14159;
💡

Nunca use var. Use const por padrão, let quando precisar reatribuir.

04 Alta Frequência

this em callbacks e arrow functions

❌ this perdido 
const obj = {
  name: 'João',
  greet: function() {
    setTimeout(function() {
      console.log(this.name); // undefined!
    }, 100);
  }
};
✅ Arrow function preserva this 
const obj = {
  name: 'João',
  greet: function() {
    setTimeout(() => {
      console.log(this.name); // 'João' ✓
    }, 100);
  }
};

// Ou bind explícito
setTimeout(function() {
  console.log(this.name);
}.bind(this), 100);
💡

Arrow functions herdam this do escopo pai. Funções normais têm seu próprio this.

05 Alta Frequência

Esquecer await em funções async

❌ Promise não resolvida 
async function getData() {
  const response = fetch('/api/data');
  const data = response.json(); // Erro!
  console.log(data); // Pending Promise
}
✅ Com await 
async function getData() {
  const response = await fetch('/api/data');
  const data = await response.json();
  console.log(data); // Dados reais ✓
}

// Com error handling
async function getDataSafe() {
  try {
    const response = await fetch('/api/data');
    if (!response.ok) throw new Error('HTTP error');
    return await response.json();
  } catch (error) {
    console.error('Erro:', error);
  }
}
💡

Sempre use await com operações assíncronas. Envolva em try/catch para erros.

06 Média Frequência

Mutar arrays/objetos diretamente

❌ Mutação direta (perigoso) 
const original = [1, 2, 3];
const copy = original;
copy.push(4);
console.log(original); // [1, 2, 3, 4] - modificado!
✅ Criar cópias 
const original = [1, 2, 3];

// Spread operator
const copy = [...original, 4];

// Para objetos
const obj = { a: 1, b: 2 };
const objCopy = { ...obj, c: 3 };

// Deep copy (objetos aninhados)
const deepCopy = JSON.parse(JSON.stringify(obj));
💡

Imutabilidade evita bugs. Sempre crie novas cópias ao modificar dados.

07 Média Frequência

forEach não funciona com async/await

❌ Não espera as promises 
const ids = [1, 2, 3];
ids.forEach(async (id) => {
  const data = await fetchUser(id);
  console.log(data);
});
console.log('Fim'); // Executa antes dos logs!
✅ Usar for...of ou Promise.all 
// Sequencial
for (const id of ids) {
  const data = await fetchUser(id);
  console.log(data);
}
console.log('Fim'); // Executa por último ✓

// Paralelo (mais rápido)
const results = await Promise.all(
  ids.map(id => fetchUser(id))
);
console.log(results);
💡

forEach ignora o retorno. Use for...of para sequencial, Promise.all para paralelo.

08 Média Frequência

Não tratar erros de Promise

❌ Erro silenciado 
fetch('/api/data')
  .then(res => res.json())
  .then(data => console.log(data));
// Se der erro, nada acontece!
✅ Com catch 
fetch('/api/data')
  .then(res => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  })
  .then(data => console.log(data))
  .catch(error => {
    console.error('Erro:', error);
    // Mostrar mensagem pro usuário
  })
  .finally(() => {
    // Esconder loading
  });
💡

Sempre adicione .catch() ou try/catch. Erros silenciosos são difíceis de debuggar.

09 Média Frequência

Confundir map, filter, reduce

❌ Uso incorreto 
// Usar map para filtrar (retorna undefineds)
const adults = users.map(u => {
  if (u.age >= 18) return u;
}); // [User, undefined, User, undefined]

// Usar forEach quando precisa do retorno
const doubled = [];
[1,2,3].forEach(n => doubled.push(n * 2));
✅ Método correto para cada caso 
// filter: retorna subset
const adults = users.filter(u => u.age >= 18);

// map: transforma cada elemento
const doubled = [1,2,3].map(n => n * 2);

// reduce: acumula em um valor
const sum = [1,2,3].reduce((acc, n) => acc + n, 0);

// find: retorna primeiro match
const admin = users.find(u => u.role === 'admin');
💡

map = transformar, filter = filtrar, reduce = acumular, find = buscar um.

10 Baixa mas Crítica

Truthy/Falsy confusão

❌ Verificação incorreta 
const count = 0;
if (count) {
  console.log('Tem items'); // Não executa!
}
// 0 é falsy, mas pode ser valor válido

const text = "";
if (!text) {
  console.log('Vazio'); // String vazia é falsy
}
✅ Verificação explícita 
const count = 0;
if (count !== undefined && count !== null) {
  console.log('Count definido:', count);
}

// Ou nullish coalescing
const value = count ?? 'default'; // 0 (não 'default')

// Valores falsy: false, 0, "", null, undefined, NaN
// Valores truthy: todo o resto, incluindo [], {}
💡

Use ?? para null/undefined, || pode substituir 0 e "" indesejavelmente.

🔧 Debug

Técnicas de Debugging

Aprenda a debugar código de forma eficiente e profissional.

📝 Console além do .log()

// Agrupar logs relacionados
console.group('Dados do Usuário');
console.log('Nome:', user.name);
console.log('Email:', user.email);
console.groupEnd();

// Tabela para arrays/objetos
console.table(users);

// Tempo de execução
console.time('fetch');
await fetch('/api');
console.timeEnd('fetch'); // fetch: 234ms

// Warning e Error (diferentes cores)
console.warn('Atenção: valor depreciado');
console.error('Erro crítico!');

// Condicional
console.assert(x > 0, 'x deve ser positivo');

// Stack trace
console.trace('Como chegamos aqui?');

// Contar ocorrências
console.count('render'); // render: 1, 2, 3...

// Limpar console
console.clear();

🔴 Breakpoints no DevTools

  • Line Breakpoint: Clique no número da linha
  • Conditional: Clique direito → "Add conditional breakpoint"
  • Logpoint: Loga sem pausar a execução
  • debugger; Pausa quando DevTools está aberto
  • DOM Breakpoint: Pausa quando elemento muda
  • XHR Breakpoint: Pausa em requisições específicas
  • Event Listener: Pausa em eventos (click, etc) 
// Breakpoint no código
function processData(data) {
  debugger; // Pausa aqui
  return data.map(item => item * 2);
}

🌐 Debugging de Rede

  • Status Code: 2xx ✓, 4xx erro cliente, 5xx erro servidor
  • Preview: Visualiza resposta formatada
  • Headers: Verifica tokens, content-type
  • Timing: Identifica gargalos
  • Throttling: Simula conexões lentas
// Log detalhado de requisições
const response = await fetch('/api/data');
console.log('Status:', response.status);
console.log('Headers:', Object.fromEntries(response.headers));
console.log('URL:', response.url);

React

Erros Comuns em React

Bugs específicos do React que pegam iniciantes e veteranos.

01 Alta Frequência

Esquecer key em listas

❌ Warning no console 
{items.map(item => (
  <Item name={item.name} />
))}
// Warning: Each child should have a unique "key" prop
✅ Com key único 
{items.map(item => (
  <Item key={item.id} name={item.name} />
))}

// ⚠️ Evite usar index como key se a ordem pode mudar
{items.map((item, index) => (
  <Item key={index} /> // Ruim se lista é reordenada
))}
💡

Keys ajudam React a identificar mudanças. Use ID único, não índice.

02 Alta Frequência

Mutar estado diretamente

❌ Mutação direta 
const [items, setItems] = useState([1, 2, 3]);

// ❌ Não causa re-render!
items.push(4);
setItems(items);

// ❌ Objeto
const [user, setUser] = useState({name: 'João'});
user.name = 'Maria';
setUser(user);
✅ Criar novo estado 
// ✅ Array - spread operator
setItems([...items, 4]);

// ✅ Remover item
setItems(items.filter(item => item !== 2));

// ✅ Objeto
setUser({...user, name: 'Maria'});

// ✅ Com callback (prevState)
setItems(prev => [...prev, newItem]);
💡

React compara referências. Sempre crie novos objetos/arrays para atualizar estado.

03 Alta Frequência

useEffect com dependências erradas

❌ Loop infinito ou efeito não executa 
// Loop infinito!
useEffect(() => {
  setCount(count + 1);
}); // Sem array de dependências

// Não atualiza quando deveria
useEffect(() => {
  fetchUser(userId);
}, []); // userId não está nas deps
✅ Dependências corretas 
// Executa apenas uma vez
useEffect(() => {
  fetchInitialData();
}, []);

// Executa quando userId muda
useEffect(() => {
  fetchUser(userId);
}, [userId]);

// Com cleanup
useEffect(() => {
  const subscription = subscribe();
  return () => subscription.unsubscribe();
}, []);
💡

Inclua todas variáveis usadas no effect. Use eslint-plugin-react-hooks.

04 Média Frequência

Estado não atualiza imediatamente

❌ Expectativa errada 
const [count, setCount] = useState(0);

const handleClick = () => {
  setCount(count + 1);
  console.log(count); // Ainda 0!
  
  setCount(count + 1);
  setCount(count + 1);
  // count ainda é 1, não 3!
};
✅ Usar callback 
const handleClick = () => {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  // Agora count será 3!
};

// Para usar valor atualizado
useEffect(() => {
  console.log('Count atualizado:', count);
}, [count]);
💡

setState é assíncrono. Use callback prev => para atualizações sequenciais.

05 Média Frequência

Renderizar condicionalmente errado

❌ Renderiza 0 
{count && <Message />}
// Se count é 0, renderiza "0" na tela!

{items.length && <List items={items} />}
// Se length é 0, renderiza "0"
✅ Conversão explícita 
// Usar comparação booleana
{count > 0 && <Message />}

// Ou ternário
{count ? <Message /> : null}

// Ou Boolean()
{Boolean(items.length) && <List />}

// Double negation
{!!items.length && <List />}
💡

0 e "" são falsy mas o React os renderiza. Force boolean com comparação ou !!.

Git

Erros Comuns em Git

Problemas de versionamento que todos enfrentam e como resolver.

01 Alta Frequência

Commit na branch errada

❌ Situação 
# Você commitou na main ao invés da feature
git log --oneline
abc1234 feat: nova funcionalidade  # Ops!
✅ Solução 
# 1. Crie a branch do commit atual
git branch feature-nova

# 2. Reset main para antes do commit
git reset --hard HEAD~1

# 3. Mude para a branch correta
git checkout feature-nova

# Alternativa: cherry-pick
git checkout feature
git cherry-pick abc1234
git checkout main
git reset --hard HEAD~1
02 Alta Frequência

Desfazer último commit

✅ Opções 
# Manter alterações staged
git reset --soft HEAD~1

# Manter alterações unstaged
git reset HEAD~1

# Descartar tudo (CUIDADO!)
git reset --hard HEAD~1

# Já fez push? Use revert (não reescreve histórico)
git revert HEAD

# Editar mensagem do commit
git commit --amend -m "Nova mensagem"

# Adicionar arquivo esquecido
git add arquivo.js
git commit --amend --no-edit
03 Alta Frequência

Conflitos de merge

❌ Arquivo com conflito 
<<<<<<< HEAD
const url = '/api/v2/users';
=======
const url = '/api/v1/users';
>>>>>>> feature-branch
✅ Resolver 
# 1. Edite o arquivo, mantendo o código desejado
const url = '/api/v2/users';

# 2. Remova os marcadores de conflito

# 3. Adicione o arquivo resolvido
git add arquivo.js

# 4. Continue o merge
git commit -m "Merge: resolve conflitos"

# Abortar merge se der errado
git merge --abort
💡

Use VS Code ou GitKraken para visualizar conflitos mais facilmente.

04 Média Frequência

Push rejeitado

❌ Erro 
git push origin main
! [rejected] main -> main (non-fast-forward)
error: failed to push some refs
✅ Soluções 
# Opção 1: Pull e merge
git pull origin main
# Resolva conflitos se houver
git push origin main

# Opção 2: Pull com rebase (histórico limpo)
git pull --rebase origin main
git push origin main

# Opção 3: Force push (CUIDADO - apenas para sua branch)
git push --force-with-lease origin feature-branch
# Nunca force push em main/develop!
05 Média Frequência

Arquivo sensível commitado

❌ Problema 
# Commitou .env com senhas por acidente
git log --all --full-history -- .env
# Mostra que .env está no histórico
✅ Remover do histórico 
# 1. Adicione ao .gitignore
echo ".env" >> .gitignore

# 2. Remova do cache (arquivo fica local)
git rm --cached .env
git commit -m "Remove .env do tracking"

# 3. Para remover do histórico completo:
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch .env" \
  --prune-empty --tag-name-filter cat -- --all

# 4. Force push (coordene com time!)
git push origin --force --all
